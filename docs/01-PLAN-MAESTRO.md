# PLAN MAESTRO DEL PROYECTO

## School Management Platform (SMP)

Estado: Documento vivo
Version: 0.2 (consolidacion OpenDev IA Framework)
Propietario: Direccion del Proyecto

---

## 1. Proposito del documento

> Este documento define la hoja de ruta oficial del proyecto desde su inicio hasta la version 1.0.

- Es el documento de mayor jerarquia para la direccion del producto.
- Toda planificacion tactica y todo sprint deben alinearse a este plan.

---

## 2. Alcance del plan maestro

- Aplica al producto School Management Platform (SMP).
- EL CERVANTISTA se considera una implementacion o configuracion particular de cliente dentro de SMP.
- Define fases de evolucion del producto, no el detalle operativo de sprints.
- Sirve como referencia principal para identificar siempre el siguiente paso del proyecto.

---

## 3. Vision del Producto 1.0

- Plataforma SaaS escolar integral para operacion academica, administrativa y de comunicacion institucional.
- Operacion multi-tenant para multiples instituciones con configuracion controlada por organizacion.
- Experiencia unificada para direccion, administracion, docentes, estudiantes y familias.
- Base confiable para decisiones operativas mediante trazabilidad y analitica institucional.
- Capacidad de crecimiento sostenible con gobernanza documental y operativa estable.

---

## 4. Reglas de gobernanza

- Este documento no describe el sprint activo.
- Este documento no contiene tareas tecnicas detalladas.
- Todo sprint futuro debe pertenecer obligatoriamente a una fase definida aqui.
- Las fases pueden ampliarse durante el desarrollo.
- Ninguna fase puede eliminarse sin decision explicita de la Direccion del Proyecto.
- Ante conflicto de planeacion, este plan maestro prevalece como marco de ruta.

---

## 5. Flujo oficial de recuperacion de contexto

START-HERE -> PLAN-MAESTRO -> ARQUITECTURA -> PLANIFICACION -> SPRINT-ACTUAL

---

## 6. Relacion con otros documentos

- Plan Maestro (este documento): direccion estrategica por fases.
- Planificacion y Sprint Activo: ejecucion tactica y trabajo vigente.
- Historial: registro cronologico de cambios.

---

## 7. Capas transversales obligatorias

- Seguridad
- Accesibilidad
- Calidad
- Observabilidad
- Multi-tenant
- Documentacion

Estas capas aplican a todas las fases y no se ejecutan como fase independiente.

---

## 8. Estructura de fases hacia el Milestone 1.0

### 8.1 Indice de Phases

1. Phase 0 - Fundacion del Producto y Gobierno Operativo
2. Phase 1 - Descubrimiento del Dominio Escolar y Modelo Operativo
3. Phase 2 - Plataforma Core SMP y MVP Academico
4. Phase 3 - Gestion Administrativa y Financiera Integrada
5. Phase 4 - Experiencia Unificada y Autoservicio por Roles
6. Phase 5 - Integraciones y Ecosistema Educativo
7. Phase 6 - Inteligencia Operativa y Analitica Institucional
8. Phase 7 - Escalamiento SaaS y Preparacion Comercial
9. Milestone 1.0 - Lanzamiento Oficial y Operacion Estable

---

## 9. Mapa de dependencias del negocio

1. Phase 0 habilita Phase 1.
2. Phase 1 habilita Phase 2.
3. Phase 2 habilita Phase 3 y Phase 4.
4. Phase 3 y Phase 4 habilitan Phase 5.
5. Phase 5 habilita Phase 6.
6. Phase 6 habilita Phase 7.
7. Phase 7 habilita Milestone 1.0.
